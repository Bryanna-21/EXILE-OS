# 3. BUILD THE SEVEN CORE MODULES

Create the following seven new implementation files.

## FILE 1 — `src/preempt.rs`

Build the hardware-driven preemption subsystem.

Required functionality:

- Timer interrupt integration.
- Scheduler preemption requests.
- Safe rescheduling from interrupt-return paths.
- Preemption-disable and preemption-enable mechanisms.
- Interrupt-safe scheduler interaction.
- Integration with C3 IRQ and timer infrastructure.
- Prevention of unsafe context switches inside critical sections.
- Single-CPU correctness, with clearly defined SMP limitations.

The kernel must be able to switch runnable threads without requiring the running thread to voluntarily yield.

## FILE 2 — `src/sync.rs`

Build the kernel synchronization subsystem.

Required functionality:

- Kernel mutexes.
- Semaphores.
- Condition variables.
- Wait queues.
- Blocking synchronization operations.
- Wake-up and timeout handling where supported.
- Lock ownership tracking.
- Lock-order rules.
- Deadlock detection or explicit deadlock-prevention checks.
- Priority inversion handling and priority inheritance where applicable.
- Interrupt-context restrictions.

Synchronization must integrate with the existing scheduler and thread lifecycle.

## FILE 3 — `src/process.rs`

Build the process-management subsystem.

Required functionality:

- Process control block.
- Process identifiers and generation-safe handles.
- Process lifecycle.
- Process creation.
- Process termination and cleanup.
- Parent/child relationships.
- Thread ownership within processes.
- Process exit status.
- Process events or a carefully designed signal-equivalent mechanism.
- Resource accounting.
- Configurable resource limits.
- Safe handling of process termination while threads are blocked or runnable.

A process must be a real kernel abstraction, not merely a renamed thread.

## FILE 4 — `src/address_space.rs`

Build per-process virtual address-space management.

Required functionality:

- Address-space abstraction.
- Address-space creation and destruction.
- Virtual memory region tracking.
- Page mapping and unmapping.
- Permission enforcement.
- User/kernel address separation.
- Address-space activation and switching.
- Mapping ownership and cleanup.
- Validation of user addresses.
- Protection against invalid or overlapping mappings.

Integrate with the existing physical memory and paging infrastructure.

Do not pretend address-space isolation exists if the implementation only tracks virtual addresses in metadata.

## FILE 5 — `src/usermode.rs`

Build user-mode execution support.

Required functionality:

- x86-64 Ring 3 transition.
- User stack initialization.
- User register/context initialization.
- Privilege-level transition.
- Syscall entry and return path.
- Safe transfer of control between kernel and user execution.
- User pointer validation.
- Protection against returning to invalid user contexts.
- Process termination on unrecoverable user execution faults.

Integrate with the existing GDT, IDT, interrupt and context-switch architecture.

## FILE 6 — `src/elf.rs`

Build the ELF64 executable loader.

Required functionality:

- ELF64 header validation.
- Architecture and executable-type validation.
- Program-header parsing.
- PT_LOAD segment processing.
- Segment bounds validation.
- Alignment validation.
- Memory permission enforcement.
- Zero-initialized BSS handling.
- Entry-point validation.
- User stack and initial execution-context preparation.
- Rejection of malformed and malicious executable images.

The loader must construct a real executable process image using the address-space subsystem.

Do not simply parse ELF headers and claim executable loading is complete.

## FILE 7 — `src/tls.rs`

Build per-thread thread-local storage.

Required functionality:

- TLS layout representation.
- TLS allocation and initialization.
- Per-thread TLS ownership.
- Thread-specific TLS data.
- x86-64 FS/GS base management as appropriate.
- TLS context-switch integration.
- TLS cleanup during thread destruction.
- Bounds and alignment validation.

TLS must remain isolated between threads and must survive context switches correctly.

# 4. INTEGRATE THE SEVEN MODULES INTO ONE SYSTEM

The seven new modules must be connected to the existing kernel.

Extend existing source files where necessary.

Expected integration points include:

- `src/sched.rs`
- `src/dispatch.rs`
- `src/thread.rs`
- `src/kernel.rs`
- `src/arch/x86_64/switch.rs`
- Existing GDT and IDT modules.
- Existing paging and physical-memory modules.
- C3 IRQ, APIC, IOAPIC and timer infrastructure.

The list is not restrictive. Use the actual repository architecture.

Required system flow:

1. Kernel initializes process and scheduler infrastructure.
2. A process is created.
3. Its address space is established.
4. An ELF executable is loaded.
5. A user stack and initial context are created.
6. A process-owned thread is initialized.
7. TLS is prepared.
8. The scheduler selects the thread.
9. The kernel enters user mode.
10. Timer interrupts trigger safe preemption.
11. Threads synchronize, block, wake and resume.
12. Syscalls and faults return control safely to the kernel.
13. Process termination releases threads, TLS, address spaces and owned resources.

The system must have explicit ownership and cleanup rules.
