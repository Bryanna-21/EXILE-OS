# Proposed ABI changes (not applied)

Batch 1 (OMNI-ABI 0.1 draft) is frozen and is not modified. This file records, separately, where
Batch 3 needed something Batch 1 does not provide. These are **proposals for a later ABI draft**; none
is binding and none has been reviewed. Wire values are not assigned.

| ID  | Proposal                                                                                                                                                                    | Why Batch 3 needed it                                                                                                                                       | Impact                                                                                         |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| P1  | Add an `OUT_OF_MEMORY` (or `NO_MEMORY`) code to A.4, distinct from `QUOTA_EXCEEDED`                                                                                         | Allocation failure inside the kernel is not the caller's quota. Batch 3 reports it as `QUOTA_EXCEEDED` because no better code exists, which hides the cause | Callers could distinguish "retry later or free memory" from "raise your limit"                 |
| P2  | Define `PEER_DEAD` (or a new `CLOSED`) for "the named address space/process was closed"                                                                                     | Batch 3 uses `PEER_DEAD` for operations on a closed space and `INVALID_HANDLE` once it is freed                                                             | Needs a decision whether a freed space and a never-existing space should look the same         |
| P3  | Add `INVALID_STATE` (already used by Batch 2) to A.4                                                                                                                        | Carried over from Batch 2 so the same set is used                                                                                                           | Documentation only                                                                             |
| P4  | State that `revoke` removes descendants and keeps the named node, requires `ADMIN`, and returns the number removed                                                          | Batch 1 describes revocation only as options                                                                                                                | New `proc`/`cap` call and a right usage rule                                                   |
| P5  | State that release re-parents children to the released node's parent                                                                                                        | Needed so that revocation authority is not lost when an intermediate node is released                                                                       | Behavioural rule                                                                               |
| P6  | Define `begin_op`/`end_op` (pinning) and `op_still_authorized` as the kernel-internal pattern for B.3 item 6 and B.8, and state that authority is checked once at the start | Batch 1 requires holding a reference for an operation's duration but does not define the revocation interaction                                             | Internal rule; may become a syscall helper for services                                        |
| P7  | Decide whether a derivation depth bound is required                                                                                                                         | Batch 1 recommends a bound. Batch 3 has none (quota-bound only)                                                                                             | If a bound is wanted, re-parenting on release must update depths, which this model does not do |
| P8  | Decide whether transfer to another process is move-only or also copy (B.2 mentions both)                                                                                    | Batch 3 implements move only; copy is derive then move                                                                                                      | Wire format of IPC handle-transfer lists                                                       |
| P9  | State the handle-table size limit (65,535 slots per space) and the retirement rule                                                                                          | Visible to users as a capacity limit and as `QUOTA_EXCEEDED`                                                                                                | Document in B.2                                                                                |
| P10 | Add `charge` ownership rule: an object's creation charge stays with the creating account even after its capability moves                                                    | Needed for the zombie-space behaviour                                                                                                                       | Ties into Batch 1 D5 (shared-object charging), which this batch does not settle                |

Not proposed, left open: R1 indirection for service-defined authority; synchronous revocation;
cancellation of running operations; process termination semantics beyond "close releases all".
