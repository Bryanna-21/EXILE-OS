# OMNI-Kernel Batch 8: bootable execution foundation (experimental, never booted)

A bare-metal x86-64 kernel image, the CPU structures behind it, a hosted test suite, and QEMU test scripts. **The image
has been built, linked and statically checked, but it has not been booted: QEMU, GRUB and the pinned bare-metal toolchain
were not available in the authoring environment.** Read `REPORT.md` first; it separates what is implemented, compiled,
unit-tested, QEMU-tested and hardware-tested.

## What is here

* `arch/x86_64/boot.S` Multiboot v1 bootstrap: serial, CPU checks, long mode, bootstrap identity map.
* `kernel/main.rs` the kernel: memory map, GDT/TSS, IDT, W^X page tables, frame allocator, expected-fault self-tests,
  scheduler scenario, timer test, and an optional ring-3 / SYSCALL stage.
* `arch/x86_64/isr.S` (generated by `scripts/gen_isr.py`), `probe.S` (fault probes, ring-3 programs).
* `src/` a hosted, tested `no_std` library holding the logic: descriptors, IDT and trap frame, paging, frame allocator,
  Multiboot parsing, timer sequences, ring-3 entry validation, self-test logic.
* `link/linker.ld`, `boot/grub.cfg`, `scripts/` (build, image and assembly checks, QEMU harness, verification).
* `tests/` 65 hosted tests and the expected serial transcripts. `docs/` design, audit, test plan.

## How Batch 8 relates to Batches 2 to 7

* **Batch 7** is a Cargo path dependency and is used unchanged: its scheduler, SYSCALL entry stub, `Kernel` dispatch, MSR
  setup and `UserBacking` trait run inside this kernel. Batch 7 assumed a GDT, TSS, IDT, paging and kernel stacks existed;
  Batch 8 provides them, and tests pin the selector layout to Batch 7's STAR value.
* **Batches 2 to 6** (Zig, hosted) share no code. They supply the capability, IPC and boundary design; the only shared
  conventions are the provisional syscall numbers and register convention. `verify.sh` re-runs them as a regression.
* **ExileKernel** has the same boot contract (Multiboot v1, 1 MiB, COM1, ISA debug exit) but is not modified or linked.
  `Kernel/` is not touched. See `docs/AUDIT.md`.

## Run

```
scripts/verify.sh                         # everything; exit 0 / 1 / 2; QEMU steps report SKIPPED when unavailable
cargo test --offline                      # 65 hosted tests (Linux x86-64, Rust >= 1.88)
scripts/build.sh --variant base --test-exit --out DIR
python3 scripts/qemu_test.py              # needs qemu-system-x86_64, grub-mkrescue, xorriso
```
Keep build output outside the repository (`CARGO_TARGET_DIR`, `--out`).

## Honest status

Not booted. No instruction of the kernel has run on a CPU or emulator. The image is built with a host-target fallback,
not rustc 1.91.1 with `x86_64-unknown-none`. No asynchronous preemption (the `preempt` variant adds tick-driven preemption requests honoured at safe points; hosted-tested, not booted), no SMP, no ARM64, no integration with ExileKernel or
`Kernel/`. See `docs/SECURITY.md` for limits.
